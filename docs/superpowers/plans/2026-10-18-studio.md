## Global constraints

- The document is structure, never HTML. Rich text = plain text with `**bold**`, `*italic*`, `[words](https://…)` only;
  links https only and shown with their address. Rendering escapes everything else.
- Freedom inside a system: every theme combination must stay readable (WCAG 4.5:1 for text, 3:1 for large text and
  controls); a custom accent is nudged darker/lighter until it passes, and the author sees «цвет чуть поправлен для
  читаемости».
- One renderer for the canvas and the participant (`components/studio/DocView.tsx`), so what the author sees is what
  the participant gets.
- Meldy design language (Onest default, warm canvas, white cards, both themes); 1532×734 and 390 without sideways scroll;
  keyboard for everything that the mouse does (drag included); `prefers-reduced-motion` respected.
- Autosave after each change (debounced 800 ms); two tabs → «Тест изменён в другой вкладке» with «Обновить».
- Plain Russian words, no exclamation marks, no AI tells.

## Data contract — database (agent S1)

Migration `supabase/migrations/20261019100000_test_docs.sql`, rollback, contract `supabase/tests/test_docs.sql`,
rehearsal `supabase/tests/local/test_docs_behaviour.sql` + `test_docs_run.sh` (base: the release-47 chain).

1. `public.test_docs (container_id uuid primary key references containers on delete cascade, doc jsonb not null, rev
   integer not null default 1, updated_at timestamptz not null default now())`, CHECK `octet_length(doc::text) <= 204800`;
   RLS on, no policies, rights revoked; access only through functions.
2. `meldy_private.test_doc_ok(p_doc jsonb, p_container_id uuid) returns text` — null when the document is valid, else the
   name of the first broken rule (`version`, `title`, `theme`, `layout`, `blocks`, `block:<n>:<rule>`, `results`). Rules
   = `types/testDoc.ts` (limits, enums, `BLOCK_ID_RE`, unique ids, `DOC_IMAGE_RE` with the exam's own folder, a question
   block's `item_id` is a test_items row of this exam and appears at most once, points 1..100, bands within 0..100 and
   not overlapping, cta url `^https://` ≤ 300).
3. `test_doc_get(p_container_id uuid) returns jsonb` — the owner only: `{container_id, doc, rev, updated_at}` or `null`
   when there is none yet. `test_doc_save(p_container_id uuid, p_doc jsonb, p_rev integer) returns jsonb {rev,
   updated_at}` — the owner only; `p_rev` must equal the stored rev (0 for the first save) else MC020 detail `stale`
   (message carries nothing; the client refetches); invalid → 22023 detail = the rule name. Deleting a question row
   leaves its block dangling: the readers skip such blocks (no cascade into the JSON).
4. Quizzes «как в студии»: `quizzes.design boolean not null default false` (quiz_apply key `design`; locked after the
   start like the set). With `design`: the attempt's items = the document's question blocks in order (all of them),
   `shuffle_items` false, `same_set` true, `item_count` = their count (ignored settings are stored as given). The taker's
   attempt JSON, the preview and the result gain `design` = `{title, theme, layout, blocks, results}` (the stored doc as
   is — it holds no keys); without `design` they carry `design: null`. The result also gains `band` = the matching
   result band (or null).

## Doc library (agent S2): `frontend/src/lib/studio/*` (+ tests), no UI

- `doc.ts`: `emptyDoc(title)`, `newBlock(type, itemId?)` (ids from `crypto.getRandomValues`, 12 chars `[a-z0-9]`),
  `docProblems(doc, itemIds)` mirroring `test_doc_ok` (same rule names), `normalizeDoc(raw)` (drops unknown fields,
  dangling question blocks kept but flagged), `questionIds(doc)`, `syncQuestions(doc, items)` (items not on the page are
  appended as question blocks at the end — a new question from «Список» or import shows up on the canvas).
- `history.ts`: an undo/redo stack of documents (100 steps, coalescing typing into one step per block within 1 s).
- `richText.ts`: parse/render-to-tokens of the three marks (no HTML), `plainOf(text)`.
- `contrast.ts`: WCAG contrast, `readableAccent(hex, bg)` (nudges until 4.5:1), `themeTokens(theme, dark)` → CSS custom
  properties used by DocView.
- `textFormat.ts`: the whole test as text and back — blocks separated by an empty line; `# ` heading, `! ` note,
  `---` divider, `===` new page, a question = stem lines then options `+ верный` / `- неверный`, `= форма` for a short
  answer, `> пояснение`; text paragraphs otherwise. `toText(doc, items)`, `fromText(text, doc, items)` →
  `{doc, adds: ItemInput[], updates: Array<{id, patch}>, removes: string[], problems: Array<{line, message}>}`; a round
  trip of a document is identity.
- `checker.ts`: `checkTest(doc, items) → Array<{id, blockId?, itemId?, level: 'fix'|'think', message, fix?: Fix}>` —
  no key; repeated stem (normalised); same option twice; the right option is clearly the longest in most questions;
  the key letter is the same in most questions (≥ 8 questions); «все перечисленные» / «нет верного» with shuffling;
  «верно / неверно» without keep_order; a short answer whose only form has a number; low contrast; an empty page; a
  question block whose row is gone. `Fix` = a patch the canvas can apply in one press.
- `templates.ts`: four starters (контрольная по теме, викторина, входной тест, самопроверка) as documents + sample
  questions (ItemInput) in plain Russian.

## Canvas UI (agent S3): `frontend/src/pages/test/StudioPage.tsx`, `frontend/src/components/studio/*` (+ tests), `App.tsx` route `exams/c/:id/studio`, `components/containers/actions.tsx` («Студия» replaces «Конструктор»), `pages/test/NewTestPage.tsx` (lands in the studio)

- Three views on one page: «Холст» (default), «Список» (the release-47 list: reuse `QuestionList`/`useBuild`), «Текст».
- Холст: palette (left; on a phone a sheet) of the block types and the question types; drag a block onto the canvas
  (`@dnd-kit/core@6.3.1`, `@dnd-kit/sortable@10.0.0`, `@dnd-kit/utilities@3.2.2` — pin exactly), or press it to add
  after the selected block; on the canvas: hover shows a handle, «Копия», «Удалить», «Выше/Ниже»; click a text to edit
  it in place; «/» on an empty line opens the block menu; Delete removes the selected block (undo brings it back).
- Inspector (right; on a phone a sheet): the selected block's settings; a question block shows the release-47
  QuestionEditor for the row (save goes to test_items as today) plus points and «обязательный».
- «Оформление» panel: the six accents + «свой цвет» (input type color, nudged by `readableAccent`), background (ровный /
  мягкий / картинка + затемнение), шрифт, скругление, плотность, ответы списком / плиткой, кнопки; four ready themes.
- Top bar: Холст/Список/Текст, телефон/компьютер, Отменить/Повторить (Ctrl+Z / Ctrl+Shift+Z), «Проверка теста» (the
  checker panel with «Исправить»), «Посмотреть как участник» (DocView in a phone or desktop frame, answering locally),
  «Отправить по ссылке» (quiz setup with `design` on and `?all=1`).
- Hints: a first-visit tour of 4 steps (stored per user in localStorage, skippable), empty test → templates + «Вставить
  готовый тест» (release 47.3) + the four question types; one contextual line near the selected block.
- Saving: load with `test_doc_get` (none → `emptyDoc` + `syncQuestions`), save with `test_doc_save` (debounced), MC020 →
  the conflict line.
