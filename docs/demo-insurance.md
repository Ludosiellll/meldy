# Страховка демо

Что проверить перед показом и что делать, если на сцене что-то сломалось. Адрес сайта: https://ludosiel-studyforge.hf.space.

## Что есть в запасе

- **`/check`** — проверка перед показом. Сама проверяет интернет и сайт, сервер, доступ к Supabase из этой сети. По кнопкам — ИИ на сервере, микрофон, распознавание речи в браузере и на сервере, голос экзаменатора. Вверху итог: «Можно показывать» или «Есть проблемы: …». У каждой проблемы написано, что сделать. Распознавание на сервере и голос проверяются только после входа в аккаунт.
- **`/try`** — пример экзамена без входа. Ответ проверяет ИИ на сервере (`POST /api/try/evaluate`, один запрос на ответ). Когда ИИ не отвечает, нет сети или проверки на сегодня кончились, пример проверяет ответ по ключевым словам прямо в браузере и пишет об этом. Supabase примеру не нужен. Голоса в примере нет — вопрос экзаменатора показывается текстом. Отвечать можно голосом (распознаёт браузер) или текстом.
- **Запасное видео** `try-walkthrough.mp4` — 82 секунды, 1440×900, без звука; в репозиторий не кладётся (релиз выкладывает всё дерево в Hugging Face), владелец получил файл в сессии 2026-10-05. Записано с живого сайта 5 октября 2026: лист примера, «почему» у двух вопросов (есть в лекциях и нет ни в одной), «Тянуть билет», ответ текстом, вопрос экзаменатора, ответ на него, протокол с оценкой. **Устарело:** оценок на сайте с выпуска 28 нет, шпаргалки и лекций в видео нет. К отбору и финалу нужно новое.
- **Ежедневная проверка в GitHub Actions** — будит сайт, проверяет ИИ и не даёт Supabase поставить бесплатный проект на паузу. Подробно — в конце.

## Чек-лист

### За день

1. Дома откройте `/check`, войдите в аккаунт для показа и пройдите все карточки. Норма — «Можно показывать».
2. Нажмите «Проверить ИИ». Должны ответить и Gemini, и Groq. Если отвечает только один, показ пройдёт, но ответы могут идти дольше.
3. Скачайте видео на ноутбук для показа и откройте его в плеере. Показывать его будете без сети.
4. Посмотрите последний запуск «Keepalive and health check» в GitHub → Actions. Красный — читайте строки с ошибками в журнале.
5. Если нужен план Б с Docker, соберите образ сейчас: сборка скачивает пакеты из интернета.
6. Зарядите телефон и проверьте, что ноутбук подключается к раздаче интернета с него.
7. Войдите в аккаунт для показа заранее (почта и пароль), чтобы не вводить их на сцене.

### За час

1. Подключите ноутбук к сети площадки и откройте `/check`.
2. Карточка «Вход и данные (Supabase) из этой сети». «Проблема» значит, что сеть площадки не пускает к supabase.co: не будут работать вход, экзамены и материалы. Переключитесь на раздачу с телефона, нажмите «Проверить ещё раз» и показывайте через телефон.
3. Подключите микрофон, который будет на сцене, и пройдите карточку «Микрофон»: столбики должны двигаться, когда вы говорите.
4. Пройдите обе проверки распознавания речи — в браузере и на сервере.
5. «Голос экзаменатора» → «Проиграть фразу». Звук должен идти туда, где его услышит зал: колонки или HDMI проектора.
6. Если голос или распознавание не работают, решите сейчас: на сцене отвечаете текстом.

### За 5 минут

1. Откройте сайт. Бесплатный Space на Hugging Face засыпает, если сайт 48 часов никто не открывал, и просыпается около минуты. Если «Сервер приложения» в `/check` — «Работает», сайт проснулся.
2. Держите открытыми вкладки: `/check`, `/try`, экраны приложения для показа и видео в плеере, на паузе на первом кадре.
3. Выключите уведомления на ноутбуке. Закройте Zoom, Teams и Telegram: они могут держать микрофон.
4. Проверьте громкость.

## Если на сцене что-то сломалось

| Что видно | Что делать |
|---|---|
| Сайт не открывается или долго висит «Загружаем страницу…» | Подождите до минуты: Space просыпается. Не помогло — показывайте видео. |
| Не получается войти, экраны пустые, ошибки загрузки | Скорее всего, сеть не пускает к supabase.co. Раздайте интернет с телефона и обновите страницу. Пока переключаетесь — показывайте `/try`. |
| ИИ отвечает ошибкой или «Сервис ИИ сейчас занят» | Показывайте `/try`: без ИИ он проверяет ответ по ключевым словам. Или видео. |
| Приложение пишет, что дневной лимит ИИ исчерпан | Войдите в запасной аккаунт или показывайте `/try`. |
| Микрофон не слышит, речь не распознаётся | В билете нажмите «Ответить текстом» (во время ответа голосом — «Текстом») и напечатайте ответ. В `/try` — так же. |
| Голос экзаменатора молчит | Вопрос всё равно на экране — прочитайте его вслух сами. |

## Страница `/check`

| Карточка | Что проверяет | Когда |
|---|---|---|
| Интернет и этот сайт | запрос к самому сайту, мимо кэша; время ответа | сама |
| Сервер приложения | `/api/health`: сервер отвечает, ключи ИИ заданы | сама |
| Вход и данные (Supabase) из этой сети | запрос к Supabase из этого браузера с публичным ключом: открыт ли supabase.co в этой сети | сама |
| ИИ и сервисы на сервере | `/api/health/deep`: сервер по-настоящему спрашивает Gemini (первую модель из списка, которая ответит) и Groq, озвучивает одно слово через edge-tts и обращается к Supabase; показывает, какая модель ответила | кнопка «Проверить ИИ» |
| Микрофон | разрешение браузера и уровень звука 6 секунд | кнопка |
| Распознавание речи в браузере | 5 секунд: браузер показывает, что расслышал | кнопка |
| Распознавание речи на сервере | 4 секунды записи уходят на сервер, он присылает текст | кнопка, нужен вход |
| Голос экзаменатора | короткая фраза голосом с сервера, без подмены голосом браузера | кнопка, нужен вход |

Результат проверки ИИ сервер хранит 10 минут. Поэтому частые нажатия не тратят дневной лимит бесплатных запросов к ИИ, но и свежий результат после исправления появится не раньше, чем через 10 минут. Перезапуск Space сбрасывает это хранение.

После «Голос экзаменатора» есть кнопка «Не слышно»: нажмите её, если фраза проиграна, но в зале её не слышно, — карточка покажет, что проверить.

## План Б: приложение на своём ноутбуке (Docker)

Когда помогает: Space на Hugging Face не просыпается или работает слишком медленно.

Когда не помогает: если сеть не пускает к supabase.co. Локальному приложению тоже нужны Supabase (вход и данные) и сервисы ИИ в интернете. В этом случае нужна раздача с телефона, а не Docker.

Что нужно:

- Docker Desktop (на Windows — с WSL 2) или Docker на Linux;
- доступ к репозиторию `Ludosiellll/meldy` — он закрытый, клонируйте под своим аккаунтом GitHub;
- ключи `GROQ_API_KEY` и `GEMINI_API_KEY` — те же, что в секретах Space. Ключи не коммитьте и не кладите в папку репозитория.

Сборку делайте заранее, дома: она скачивает пакеты npm и pip.

### Windows (PowerShell)

```powershell
git clone https://github.com/Ludosiellll/meldy.git
cd meldy
git checkout claude/relaxed-hypatia-1tpmq5
docker build -t meldy .

# Ключи — в файл рядом с репозиторием, не внутри него. Подставьте свои значения.
Set-Content -Path ..\meldy.env -Encoding ascii -Value @(
  'GROQ_API_KEY=ваш_ключ_groq',
  'GEMINI_API_KEY=ваш_ключ_gemini'
)

docker run --rm -p 7860:7860 --env-file ..\meldy.env meldy
```

`-Encoding ascii` нужен для Windows PowerShell 5: без него файл сохранится в UTF-16, и Docker его не прочитает.

### Linux и macOS

```bash
git clone https://github.com/Ludosiellll/meldy.git
cd meldy
git checkout claude/relaxed-hypatia-1tpmq5
docker build -t meldy .

# Ключи — в файл рядом с репозиторием, не внутри него. Подставьте свои значения.
cat > ../meldy.env <<'EOF'
GROQ_API_KEY=ваш_ключ_groq
GEMINI_API_KEY=ваш_ключ_gemini
EOF

docker run --rm -p 7860:7860 --env-file ../meldy.env meldy
```

Откройте http://localhost:7860/check и пройдите проверку, как на сайте.

### Переменные

| Переменная | Нужна? | Что это |
|---|---|---|
| `GROQ_API_KEY` | да | Groq: быстрые проверки ответа, распознавание речи на сервере |
| `GEMINI_API_KEY` | да | Gemini; можно несколько ключей через запятую |
| `GEMINI_MODELS`, `GROQ_MODEL`, `GROQ_FAST_MODEL` | нет | списки моделей, если в Space они заданы не по умолчанию — перенесите те же значения |
| `SUPABASE_URL`, `SUPABASE_KEY` | нет | без них сервер берёт адрес и публичный ключ того же проекта |
| `DIAGNOSTICS_USER_IDS` | нет | id владельца для `/api/diagnostics/models` |
| `TRY_GEMINI_API_KEY` | нет | ключ Gemini из отдельного проекта Google для проверки ИИ в примере `/try` (можно несколько через запятую). Без него пример берёт основные ключи, но не больше `TRY_AI_DAILY_CAP_SHARED` проверок в сутки |
| `TRY_AI_DAILY_CAP`, `TRY_AI_DAILY_CAP_SHARED` | нет | проверок ИИ в примере за сутки (по Тихоокеанскому времени): на своём ключе — 400, на основных — 60; дальше пример проверяет по ключевым словам и пишет об этом |
| `TRY_AI_CLIENT_LIMIT` | нет | предел проверок примера с одного адреса, по умолчанию `12/10 minutes;40/day`; если зал сидит за одним Wi-Fi, поднимите, например `60/10 minutes;300/day` |

Аргументы сборки `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` тоже не обязательны: без них фронтенд обращается к тому же проекту Supabase. Передать их явно можно так (значения публичные, лежат в `frontend/.env`): `docker build --build-arg VITE_SUPABASE_URL=… --build-arg VITE_SUPABASE_ANON_KEY=… -t meldy .`

Ограничения локального запуска:

- микрофон и распознавание речи работают на `http://localhost`; с другого устройства по IP-адресу браузер микрофон не даст — нужен https;
- вход через Google на localhost может не работать, если адрес не добавлен в настройках входа Supabase (не проверено). Входите по почте и паролю.

## Ежедневная проверка в GitHub Actions

Файл `.github/workflows/keepalive.yml`, название в Actions — «Keepalive and health check». Запускается каждый день в 05:17 UTC (08:17 по Москве) и вручную. Секреты не нужны: адрес Supabase и публичный ключ берутся из `frontend/.env`, который уже лежит в репозитории. Релиз в Space этот файл не трогает.

Что делает по шагам:

1. Одно чтение из базы Supabase через REST (`/rest/v1/quests?select=id&limit=1`). По документации Supabase бесплатный проект ставится на паузу, если за 7 дней в базе почти не было запросов; ежедневный запрос не даёт поставить его на паузу.
2. Открывает сайт и ждёт, пока `/api/health` ответит «ok» (до 10 минут). Заодно будит Space: по документации Hugging Face бесплатный Space засыпает после 48 часов без посещений.
3. Вызывает `/api/health/deep`. Если какая-то проверка не прошла, в журнале запуска появляется строка `::error`, например `gemini is down: Gemini, code=rate_limited after 8001 ms`, запуск становится красным, и GitHub присылает письмо о сбое.

Коды в строках ошибок: `timeout` — не ответил вовремя, `rate_limited` — упёрся в лимит запросов, `not_found` — модель недоступна, `permission` — ключ не подходит, `network` — нет связи, `unconfigured` — нет ключа, `http_503` и подобные — ответ Supabase с ошибкой.

До релиза с `/api/health/deep` третий шаг будет красным со строкой «answered 401 without the check list» — это ожидаемо.

### Чтобы проверка заработала

GitHub запускает проверку по расписанию и вручную только из ветки по умолчанию, а это `main`. Сейчас файл есть только в рабочей ветке `claude/relaxed-hypatia-1tpmq5`. Перенесите его в `main` один раз.

Через сайт GitHub: откройте репозиторий на ветке `main` → Add file → Create new file → имя `.github/workflows/keepalive.yml` → вставьте содержимое файла из рабочей ветки → Commit changes.

Или через git:

```bash
git fetch origin
git checkout main
git pull
git checkout origin/claude/relaxed-hypatia-1tpmq5 -- .github/workflows/keepalive.yml
git commit -m "Add the daily keepalive and health check"
git push origin main
```

Сделайте этот коммит сами, под своим аккаунтом. По документации GitHub письма о сбоях проверки по расписанию получает тот, кто добавил расписание в файл или последним его менял. Письмо придёт, если в настройках уведомлений GitHub включены уведомления Actions.

Ручной запуск: GitHub → Actions → «Keepalive and health check» → Run workflow → ветка `main` → Run workflow. Удобно запустить за день до показа и утром в день показа.

## Что не проверено

- Распознавание речи в Chrome идёт через сервис Google. Работает ли оно без доступа к Google за счёт языковых пакетов на устройстве, для русского языка не проверено. Считайте, что без Google распознавание в браузере не работает. В билетах приложение тогда само переключается на распознавание на сервере, а в `/try` — отвечайте текстом.
- Сборку и запуск в Docker при подготовке этой памятки не проверяли: ни на Linux, ни на Windows, ни на Mac (в среде разработки Docker не запущен). Команды стандартные, а Dockerfile тот же, по которому собирается Space. Поэтому план Б стоит один раз прогнать дома заранее.
- Озвучку внутри `/api/health/deep` не удалось запустить по-настоящему из среды разработки: её сеть не пускает к сервису edge-tts. На сервере это тот же движок, что озвучивает экзаменатора.
- Вход через Google на localhost (см. план Б).
